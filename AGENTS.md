# Halftype (formerly Itda): what a future agent must know

A menu-bar Mac app: inline Korean and English suggestions from a local model. Read `docs/how-it-works.md` first.

## Must not break
- **No private text, ever.** Nothing from anyone's messages goes in this repo: not tests, docs, commit messages or screenshots. Test strings are invented, and benchmark results are aggregates only. Replay traces hold typed text and stay out.
- **Privacy claims in the README are promises.** No network except `ModelStore`'s model URLs, Sparkle's update feed and, once it ships, Personal Model's opt-in training upload (README Privacy), no typed text written to disk or logs, no Screen Recording, secure fields skipped. A change that touches one changes the README in the same commit.
- **Licences.** AGPL, GPL and unlicensed projects in `CREDITS.md` gave ideas only. No code from them. A new borrowed idea gets a row there, with its licence checked.
- **https://halftype.app serves `docs/site/a2`** (publish with `docs/site/deploy.sh`) **and repeats the README's claims and numbers.** Change them together, and redeploy.
- **Every number carries how it was measured**, here or in `docs/measuring.md`. Remeasure rather than edit one by hand.

## Commands
- Tests: `swift test --disable-keychain -j 2`. Add `HALFTYPE_MODEL=<gguf>` for the model tests, which otherwise skip.
- App: `scripts/build-app.sh`, output `build/Halftype.app`. Renamed from Itda on 2026-11-08, everywhere: bundle ID `app.halftype.Halftype`, modules, repo `hrsong99/halftype`, cask `halftype`. `moveFromItda` carries the old folder and settings over once. Checkouts are `halftype` and `halftype-train` (the private repo below), the lab `~/halftype-lab-private`, signing `~/.config/halftype-signing` and the `halftype-signing` keychain; `itda*` symlinks to them stay for old T3 history. Only the tag `bench-1`'s `itda-replay` keeps the old name. The app needs `Halftype_HalftypeApp.bundle` (the model logos) in Contents/Resources, which `build-app.sh` copies, or `Bundle.module` stops it at launch.
- Private-window checks: `scripts/e2e.sh`, plus `--onboarding` (first lesson after the grant), `--races` (30 s, for one failing check), `--measure <gguf>`, `--flicker`, `--engine <gguf>`. `--ime` switches the system's input source and needs the user idle.
- Window PNGs with no focus taken: `HALFTYPE_SHOTS=<dir> swift test --disable-keychain --filter WindowShots`. Off-screen shots leave out the window's blurred ribbon (a SwiftUI Canvas); judge it from `15` (the whole window at three sizes, at the field and scrolled to the settings): ImageRenderer draws no ScrollView, so those are a real window ordered in behind everything, never key, and `screencapture -l`. Glass suggestions, as drawn over our own field: `halftype-e2e --shots <dir>` (`glass`, `glass-wrap`), and the Tab glint over taken words (`glint-30`, `glint-60`).
- Release: write `docs/releases/<v>.md`, then `scripts/release.sh <v>`; it refuses a dirty tree, so with another session's uncommitted files run it from a worktree of `main` on a throwaway branch (it pushes that branch: delete it after).
- Usage: `scripts/usage.sh` (GitHub download counts; the app sends nothing). Pricing and the early-bird list: `docs/pricing.md`.
- Always pass `--disable-keychain`: without it the first SwiftPM download of llama.cpp can hang on keychain credentials.
- **`scripts/e2e.sh` takes the user's keyboard and cursor focus while it runs. Ask them first, every time.** A 60 s pause in typing doesn't mean they have stopped using the Mac. Unit tests and reviews don't take focus.
- **`bench/compare/run.sh` (the typing comparison with other apps) takes the keyboard, pointer, front window and input source for ~50 minutes and launches rival apps. Ask first, every time;** `--check` is safe.
- The Mac has limited memory: run one heavy build or model at a time, and don't steal focus.
- Motion in the window: suggestions appear at once and never animate (they change on every key), and nothing resizes or moves on a Tab; the one motion is a quick glint over the words just taken (`GlintView`). John found a whole-field glint and a 0.6% breathe both bad. In other apps the host's text rarely sits exactly where the ghost was, so a Tab's motion (`AcceptMotion`, Trail or Flash in General) is drawn from the caret rects the host reports, never over letters.
- `docs/icon/generate.sh` makes icon options, with Codex's image tool. `docs/icon/build.sh d` rebuilds `Resources/`. The window's `Mark` (Window.swift) draws `docs/icon/menubar.svg`'s paths by hand: change the logo, change it too.
- Several sessions work in this checkout at once. Commit only your own files (`git commit -- <paths>`, never `-a`); if another session has uncommitted changes in a file you need, work in a separate worktree of `main` and leave theirs alone.

## Where things are
- `HalftypeCore`: pure logic, with no model or GUI. Test it here first.
- `HalftypeEngine`: llama.cpp, pinned by URL and checksum in `Package.swift`.
- `HalftypeApp`: Accessibility, key tap, panel, and the window (`Window.swift`). Swift 5 language mode, as state is confined by hand to one queue.
- The tag `bench-1` keeps the replay harness (`itda-replay`), removed from main. Don't move it.
- Learning from use and Personal Model training: the private repo `hrsong99/halftype-train` (checkout `../halftype-train`, branch `train`, tracking its `main`), which is this repo plus `lab/` and `halftype-replay`, merging this `main` in. Nothing from it comes back here; read its `lab/PLAYBOOK.md`. Only a per-user LoRA moved keys saved; prompt, logit and gate methods were ~0. Judge any prompt change against the screen-context baseline there.
- General > Show What the Model Sees (off by default): a tap of ⌃⌥ (`PeekTap`) toggles `PeekPanel` (`Peek.swift`) over every ghost, ⌃⌥⇧ the whole prompt; numbers from `Peek.make` (Generation.swift), which must follow `Stop.cut`'s rules. Modifiers are watched by NSEvent monitors, never taken by `KeyTap`; the card drops its text when it hides.
- Personal model: the `*.gguf` files in `~/Library/Application Support/Halftype/adapters/<model file>/`, for that model only (from `lab/dogfood/train.sh` in halftype-train: `john-<date>`, then `-2`, `-3` the same day), show General > Personal Model, with one row per version (newest first; title from the date in the name, note from its `<name>.json`: messages and their dates; where and how it trained stay in the file, as users' versions will all come from our server) to Use or delete. With none chosen the newest is used, so a new one takes over and an older one is a rollback. Each day in `stats.json` names the adapter it ran, so Stats sets versions side by side. Compare leaves it off on even dates, and Stats sets the two kinds of day side by side. `shown` in `stats.json` counted every streamed word until cf8b6bd (2026-11-09), so `lab/dogfood/ab.py`'s take rate is only good from 2026-11-10 on.
- The local branch `bench-2` (worktree `../local-autocomplete/bench2-worktree`) replays the shipped policy; the 2026-11 numbers in `docs/measuring.md` come from it, run by `../local-autocomplete/experiments/bench2/run.sh` and scored by `report.py` there.

## Traps
- Accessibility grants are pinned to the signing certificate. The Developer ID build can't use a grant made for an Apple Development build, and a relaunch silently loses it. To keep one, re-sign that copy with the granted certificate and check it with `codesign -v -R <csreq from TCC.db>`.
- Activity Monitor's per-app Memory hides what Metal wires, about the model's file size. Read `docs/measuring.md` before claiming a memory number.
- `Gate.threshold` is fitted for English, and no Korean threshold exists. Don't tune it on Korean.
- A delayed cleanup belongs to the input revision that scheduled it. A successful field read is not a successful display.
- AX on our own window (Try It) is answered in-process on the asking thread, and SwiftUI crashes off main. Read through `AX.get`, which hops to main for our pid (`AX.own`); a test that blocks main must not wait on the watcher. There our ghost panel is a window of the watched app too: its AX notifications reach our observer, so filter them by `GhostPanel.accessibilityID`.
- The 0.3 s Tab hold (`KeyTap.State.held`) is for Tabs that outrun a streaming or clipped suggestion, not for our panel's AX moves (that is `GhostPanel.accessibilityID`). facc6e6 removed it with the other fix, and rapid Tabs in Try It typed a tab again.
- ggml asserts if a model is still loaded at exit: the app must unload on quit.
- A main button is `.buttonStyle(Ink())` (Onboarding.swift), never `.borderedProminent` with `.tint(.primary)` (black on black when key) or `.tint(.secondary)` (SwiftUI crashed). Window shots are never key, so they don't show the first.
- Since macOS 14 `NSApp.activate()` can't take the front from the active app: after the grant, Halftype came up inactive behind System Settings. `App.tapChanged` uses the deprecated `activate(ignoringOtherApps:)`, which still works; keep it. AX also answers `apiDisabled` for a moment after the grant, so `Watcher.attach` retries; check a grant end to end with `tccutil reset Accessibility app.halftype.Halftype` and a real Touch ID.
- Live checks of our own window: launch with `open -a build/Halftype.app --args …`. A binary started from the shell never becomes the front app, so the watcher binds to whatever was in front. Steps in the window fade, never slide: a ghost is placed when its field is read, and a moving field sends no AX move.
- Drawing shared by an NSView and a SwiftUI Canvas (`AcceptMotion.draw`) goes into the `CGContext` it's given: `NSGradient` and `NSBezierPath` draw into AppKit's current context, which `withCGContext` doesn't set, so the Canvas shows nothing. A test that sets `NSGraphicsContext.current` hides it.
- The window shots never run a view's `.task` or main-actor `Task` (the test holds the main actor). Draw motion as a function of elapsed time in a `TimelineView`, as `Welcome` does, and any moment can be shot.
- Automatic tests don't reach Chromium's composition or real Tab. After any change to accepting or reading, run `docs/live-test.md`.
- An agent can run most of `docs/live-test.md` itself while the user is away: start `build/<app>/Contents/MacOS/Halftype` from the shell (it inherits the terminal's Accessibility; a newly signed build's own grant needs Touch ID), bring the host app forward, type with `scripts/live-keys.swift`, and `screencapture -x` the screen. For motion, `screencapture -v -V <s> -x out.mov` records 60 fps and `ffmpeg -vf "crop=…,tile=1x24"` makes a frame strip; press Tab only while a ghost shows (stop mid-word, e.g. "…if you ha"), or it types a tab. The first launch of a freshly built copy started this way sometimes shows no ghost at all (Tab types a tab); relaunch it and check a ghost shows before trusting the run. John updating through Sparkle didn't hit it (0.1.12). Modifier-only keys (⌃⌥ for the model card): post a `CGEvent` keyboard event with its `type` set to `.flagsChanged`, key codes 59 and 58. Not codex-cu: it drives apps in the background, Halftype follows the frontmost one, its window shots miss the ghost panel, and a stuck `SkyComputerUseService` doubles every key (`pkill -f SkyComputerUseService`).
