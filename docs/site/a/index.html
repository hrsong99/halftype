Korean, finished mid-syllable

The syllable you are composing stays out of the prompt, and the model must answer in keys that fit it: 하 allows 한 or 함. Tab then presses the remaining keys, so the input method finishes the syllable itself.

On 1,099 mid-syllable requests in public Korean text, keystrokes saved per request went from 0 to 0.69. It costs more wrong suggestions: 18.2%, against 8.4%.

Nothing you type leaves your Mac. It keeps counts, never text.

  • One permission

    Accessibility. Never Screen Recording.

  • Network

    Model files from Hugging Face, each checked by SHA-256, and an update check on GitHub about once a day, which you can turn off.

  • On disk

    Settings and model files. No typed text, no logs.

  • Password fields

    Skipped. It reads nothing from a secure field.

Limits of this early release

Used so far by its author. Please open an issue on GitHub with what you find.

Which Macs?

macOS 26 or later. Only tested on Apple Silicon, on one M5.

Which Korean layout?

Apple’s 2-Set Korean. With another layout it shows nothing after a Hangul character.

How good is Korean?

Weaker than English: about a fifth of shown suggestions match exactly with the default model, a third with Kanana 1.5.

Where won’t it suggest?

With text after the caret on the same line, and while Secure Input is on.

Does it work in Chromium apps?

Korean has been used by hand in T3 Code, a Chromium app. Other Chromium apps haven’t been tried yet.

Building it yourself

Yes, with Swift 6.2. Without a stable signing identity it asks for Accessibility again after each rebuild.

  • 사용법

    Tab은 다음 단어, Shift-Tab은 전체, Esc는 닫기입니다.

  • 다른 점

    조합 중인 글자는 모델에 보내지 않고, 두벌식 키 입력에 맞는 결과만 받습니다.

  • 비용

    입력 중과 그 후 15초 동안 약 0.56 GB를 점유하고, 5분 쉬면 79 MB로 줄어듭니다. 모델은 처음 한 번 0.5 GB를 받습니다.

  • 개인정보

    입력한 글은 저장하지 않고 횟수만 셉니다. 비밀번호 칸은 건너뜁니다.

  • 한계

    macOS 26, Apple Silicon, 두벌식이 필요합니다. 한국어를 많이 쓴다면 Kanana 1.5를 고르세요.

  • 제거

    종료 후 휴지통으로 옮기고 ~/Library/Application Support/Halftype를 지우세요.
